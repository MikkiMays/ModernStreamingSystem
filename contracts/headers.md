# Заголовки запросов к ядру

Заголовки, которые меняют решение ядра, но не входят в тела запросов, — поэтому OpenAPI их не
описывает. Источник решений — `docs/architecture/target-2026-10.md` §1.2 и §3.1 (строки 4–5).

## `X-Cord-Profile` — профиль устройства

| | |
| --- | --- |
| Значение | секрет профиля устройства: 43 знака base64url (32 случайных байта) — тот же, что браузер хранит в `cord:profile:v1` и отдаёт избранному как `Authorization: Bearer` |
| Куда | во все входы во встречу: `POST /api/v1/rooms`, `POST /api/v1/rooms/{id}/join`, `POST /api/v1/rooms/join-by-code`, `POST /api/v1/rooms/{id}/rejoin`, `POST /api/v1/favorites/{id}/join` |
| Обязателен | нет. Без него (старый клиент, службы) вход работает как раньше, а правило одной встречи не применяется |
| Не похож на секрет | считается отсутствующим, вход не ломается |
| Что хранит ядро | `SHA-256` секрета (`profileHash`) в `RoomState.profiles` — участник → хэш. Наружу не отдаётся никогда: ни в снимке, ни в списке участников |
| Разбор | `server/.../access/Identity.java` — одно место на ядро |

Службы (бот, кинозал, музыка) этого заголовка не присылают: Telegram-беседа входит своим профилем
избранного, и правило одной встречи её не касается.

## `X-Cord-Leave` — выйти оттуда и войти сюда

| | |
| --- | --- |
| Значение | `roomId` встречи (UUID), которую человек согласился покинуть |
| Куда | тот же вход, повтором после `409 ALREADY_IN_MEETING`, с тем же телом и тем же `commandId` |
| Что делает | в одной транзакции под общим замком: выход профиля из названной встречи — обычный, как по кнопке «Выйти», остальные его видят и слышат, — и вход сюда. Откажи вход по другой причине — выход откатывается |
| Названа не та встреча | снова `409 ALREADY_IN_MEETING`, уже с той встречей, где профиль сейчас |
| Не похоже на UUID | считается отсутствующим |

## `X-Cord-Proof` — ответ на задачу «не бот» (E11-B)

| | |
| --- | --- |
| Значение | base64 от JSON `{algorithm, challenge, number, salt, signature}` — протокол ALTCHA, первая версия (SHA-256, `maxnumber`) |
| Откуда | `GET /api/v1/proof?for=create\|code` → `{algorithm: "SHA-256", challenge, maxnumber, salt, signature}`; `204` — проверка выключена (`stream.abuse.human-check: off`). Предел — 60 в минуту на адрес |
| Куда | `POST /api/v1/rooms` (задача `create`) и `POST /api/v1/rooms/join-by-code` (задача `code`) |
| Обязателен | да, пока `human-check: proof-of-work`; без него или с чужим — `403 PROOF_INVALID`. Службы с верным `X-Service-Secret` его не присылают |
| Привязка | в соли — срок (5 минут), действие и отпечаток адреса; ответ годится один раз |
| Цена | `maxnumber` = `stream.abuse.proof-cost` (50 000); ×4, если адрес выбрал половину своего предела, ×8, пока включён «щит» |
| Разбор | `server/.../access/ProofOfWork.java`; решатель браузера — `web/src/core/proof-solve.ts` (фоновый поток) |

## `X-Cord-Actor` — от чьего имени действует служба (E11-B, A11)

| | |
| --- | --- |
| Значение | `tg:<32 hex>` — HMAC номера пользователя Telegram ключом актора (`actor`, HKDF из `INTERNAL_SECRET`, A14) |
| Куда | запросы бота, сделанные по команде пользователя: создание встречи, открытие её из избранного |
| Когда ядро ему верит | только вместе с верным `X-Service-Secret`; иначе заголовок ничего не значит |
| Что делает | пределы на адрес (`stream.abuse.per-ip.*`) считаются по нему, а не по 127.0.0.1 службы |

Шлюз срезает `X-Service-Secret` и `X-Cord-Actor` у запросов снаружи (`infra/Caddyfile`, `/api/v1/*`).

## `X-Service-Secret` и `X-Internal-Secret` — свои (A14)

| | |
| --- | --- |
| `X-Service-Secret` | ставит служба (бот, музыка, кинозал): ключ `service` — HKDF-SHA256 от `INTERNAL_SECRET`, соль `cord-internal-secret`, base64url без `=` (`server/.../access/InternalKeys.java`, `services/cord_services/keys.py`). Открывает `/internal/`, проходит пароль сервера, делает `X-Cord-Actor` правдой. Сам секрет в этом заголовке — `403` на `/internal/` и не служба |
| `X-Internal-Secret` | ставит только шлюз — сам `INTERNAL_SECRET` (Caddy ключей не выводит): «пришло через нашу дверь», открывает `/internal/` и `X-Real-IP`, но не пароль сервера и не актора. Службы его не шлют |

## Ответы

### `409 ALREADY_IN_MEETING`

У профиля из `X-Cord-Profile` живое участие в другой открытой встрече: место занято (`WAITING`,
`JOINING`, `CONNECTED`, `RECOVERING`) и срок восстановления не вышел. Та же встреча во второй вкладке —
не вторая встреча; восстановление связи — то же участие. Боты не считаются.

```json
{
  "status": 409,
  "code": "ALREADY_IN_MEETING",
  "detail": "Вы уже во встрече «Наша встреча»",
  "roomId": "6c01abcf-2831-466e-8231-f228ab067bf2",
  "title": "Наша встреча"
}
```

Выключается настройкой `stream.meeting.one-active-per-profile: false`
(`ONE_ACTIVE_MEETING_PER_PROFILE`).

### `409 FAVORITES_FULL`

В избранном профиля уже `max` комнат (`stream.favorites.max-saved`, 10; `capabilities.favoritesMax`).
Уже сохранённое повторно — не отказ; сохранённое сверх предела раньше не удаляется.

```json
{ "status": 409, "code": "FAVORITES_FULL", "detail": "В избранном нет места (предел — 10). …", "max": 10 }
```

### `409 ROOM_FULL`

Во встрече `stream.max-participants` людей (20). Бот музыки места не занимает.

### Отказы антибота (E11-B)

| Код | Статус | Когда |
| --- | --- | --- |
| `ROOMS_PER_HOUR` | 429 | адрес или профиль создали `rooms-created` встреч за час (`stream.abuse.per-ip`, `per-profile`); отказ предела не съедает |
| `OPEN_ROOMS` | 429 | с адреса или профиля уже идут `open-rooms` встреч, занимающих место на сервере |
| `CODE_MISSES` | 429 | адрес промахнулся кодом `code-misses` раз за окно; до конца окна не входит по коду даже верным |
| `CODE_INVALID` | 404 | кода нет **или встреча завершена** — одинаково, чтобы не было оракула |
| `PROOF_INVALID` | 403 | нет ответа на задачу «не бот», он чужой, устарел или уже предъявлен; веб повторяет вход один раз со свежей задачей |
| `CHAT_RATE` | 429 | участник отправил `chat-messages` сообщений за окно |
| `CHAT_REPEAT` | 429 | то же сообщение подряд раньше `chat-repeat` |
| `NAME_INVALID` | 400 | имя пусто после очистки от невидимых символов |
| `NAME_RESERVED` | 400 | имя под Cord, администратора, модератора или поддержку |
| `TITLE_INVALID` | 400 | название встречи пусто после очистки |
| `FILE_TYPE_BLOCKED` | 415 | файл может запустить программу, а `stream.chat.executable-attachments: block` |
| `PASSWORD_MISSES` | 429 | адрес ошибся паролем сервера `password-misses` раз за окно |
| `RATE_LIMITED` | 429 | общий предел частоты (входы, сокеты, сигналинг, задачи «не бот») |

`MESSAGE_LIMIT` больше не отвечается: история комнаты — кольцо (`stream.chat.room-history`).
