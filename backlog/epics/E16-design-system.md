# E16 — Дизайн-система и премиальный облик

Волна 1, раньше всех экранных эпиков: E02, E03, E04, E06-B, E07, E08 и E01-B строят на ней.

## Задачи владельца

- T47 «Нужен дорогой интерфейс, но и сочесть его с кордом, либо сделать большой рефакторинг и
  глобальное обновление, разрешения все даю, нужно улучшать систему.»
- T39 (часть) «…кардинально переработать frontend»
- T24 (основа) «Лого не должно быть текстом вообще, учесть это в каждом уголке системы»
- T46 (основа) — ручка изменения ширины «как везде вообще».
- T55 «фотку догрузил, там как загрузка покера, но как сможешь заметить, оно всецело
  заполоняет пространство, я видел еще пару таких вебаппов, нужно прошарить гиты и различные
  решения, выбрать наиболее лучшее для современной системы.» — компонент полноэкранной
  загрузки и язык движения (П14).
- T54 (основа) — визуальный облик установщика: картинки мастера, иконка, заставка.

## Что уже есть

- Стили — CSS-файлы без системы: `styles.css` на 3,5 тыс. строк, плюс `room-layout.css`,
  `room-polish.css`, `game-polish.css` (с переопределениями по весу) и по файлу на игру.
  Tailwind 4 подключён. Компоненты — Base UI напрямую, примитивы в `ui/primitives.tsx`.
- Токены цветов и поверхностей частично есть (`docs/frontend.md` → «Практики»).
- Референсы владельца — `refs/README.md`: звонок и настройки Discord, настройки FACEIT,
  панель и меню ChatGPT, загрузка Cardbox, выбор сервера с круглыми флагами.
- Иконка `Cord.ico` и иконки PWA — та же марка; в SVG марки, похоже, нет — проверить.

## Шаги

1. **Аудит.** Каталог всех цветов, размеров шрифта, отступов, радиусов, теней, z-index и
   длительностей анимации, которые реально встречаются в CSS (скриптом, с частотой). Список
   переопределений по весу и `!important`. Скриншоты ключевых экранов (из E00).
   **Готово:** отчёт в спецификации с числами: сколько разных значений каждого вида.

2. **Направление.** Скилл `frontend-design`. Ориентиры владельца — Discord и FACEIT, его
   скриншоты Discord и ChatGPT разобраны в `backlog/refs/README.md`; рядом
   Linear, Arc, Raycast. «Дорогой, но Cord»: тёмная медиасцена, спокойные поверхности, точная
   типографика (Inter Variable уже локально, с кириллицей), глубина слоями и светом, а не
   рамками, движение короткое и физичное, `prefers-reduced-motion` соблюдается. Две-три
   версии ключевого экрана встречи и настроек — HTML-макетами в `backlog/screens/E16/` — и
   выбор одной с объяснением. Вопрос владельцу не задаётся: выбор фиксируется в
   `DECISIONS.md`, картинки лежат рядом.
   **Готово:** выбранное направление описано словами и показано картинками.

3. **Токены и примитивы.** Слои токенов (сырые → смысловые → компонентные) в CSS-переменных
   для обеих тем; шкалы отступов, радиусов, теней, движения; слои z-index одним списком
   (меню 40, диалоги 50 — уже договорено). Примитивы: кнопка,
   иконочная кнопка, поле, ползунок (фокус-кольцо только для клавиатуры — `:focus-visible`;
   это T31), переключатель, вкладки, меню, диалог, тост, бейдж SOON, карточка, разделитель
   панели с ручкой (`col-resize`, видимая полоса при наведении и перетаскивании, клавиатура,
   запоминание ширины — общий хук для T46), марка Cord.
   **Готово:** у каждого примитива есть страница-витрина (маршрут разработчика или
   Storybook-подобная страница без новой зависимости, если её можно избежать) со всеми
   состояниями в обеих темах.

4. **Марка (T24).** SVG-марка и словесный знак **рисунком**, а не текстом. Компонент `Logo`
   с вариантами (знак, знак+имя, монохром). Из той же марки — `Cord.ico`, иконки PWA,
   favicon, изображения установщика, превью ссылок (Open Graph). Поиск по всем репам: каждое
   место, где «Cord»/«cord» стоит как логотип, — заменить; где это имя в тексте — оставить.
   **Готово:** `grep` по обеим репам с разбором каждого вхождения в журнале; скриншоты всех
   мест, где была текстовая марка.

4а. **Полноэкранная загрузка (T55, П14).** Сначала исследование: прошерстить GitHub и готовые
   решения для полноэкранных загрузочных сцен в веб-приложениях и Mini App (CSS 3D + WAAPI
   без зависимостей, Lottie/dotLottie, Rive, Motion, Three.js/R3F — и открытые Mini App с
   такими экранами). Таблица: вес в бандле, fps на слабом телефоне (замер в Playwright с
   троттлингом CPU ×4–×6), работа в WebView Telegram, Electron и WebView2, офлайн, лицензия,
   удобство своих сцен. Выбор — с причиной в `DECISIONS.md` → «Решено агентом». Затем
   компонент `FullscreenLoader`: занимает весь экран, тёмный фон из токенов, живая сцена в
   центре (по умолчанию — из марки Cord; игры передают свою, E08), марка под сценой, без
   полосы прогресса и слова «загрузка»; уважает `prefers-reduced-motion` (статичный кадр);
   показывается, пока грузится настоящее, и исчезает плавно, без задержки, если всё уже
   готово; цвет фона задан в HTML до загрузки JS — без белой вспышки. Подключить к старту веба
   (`index.html` → React), окно Electron (E01) и Mini App (E09) пользуются им же.
   **Готово:** витрина с загрузкой в обеих темах и с `reduced-motion`; видео/кадры сцены;
   замер fps и веса бандла до/после в журнале.

4б. **Облик установщика (T54).** Картинки мастера (большая и малая), иконка, заставка
   обновления — из марки и токенов, в размерах, которые требует выбранный в E01 установщик,
   для обычного и высокого DPI.

5. **Миграция.** Перевести существующие экраны на токены и примитивы без смены вёрстки —
   поведение то же, значения из системы. Убрать переопределения по весу, переписав исходные
   правила. Экраны, которые полностью переделывают E02/E03/E04, мигрировать не нужно — они
   сразу пишутся на системе.
   **Готово:** число разных литеральных значений из шага 1 упало в разы (цифры до/после);
   скриншоты до и после на 7 ширинах не показывают поломок; e2e зелёные.
