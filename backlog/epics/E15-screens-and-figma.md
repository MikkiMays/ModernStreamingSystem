# E15 — Каталог экранов, чёткость и Figma

Волна 5, когда экраны переделаны. Аудит «как есть» уже снимают E00 и E16 — этот эпик
собирает итог.

## Задача владельца

T29 «…также везде и грамотно проверить разметку и четкость отображения на каждом экране
системы, занести все экраны в ФИГМУ» (настройки — E03).

## Шаги

1. **Перечень экранов и состояний.** Из кода (маршруты, диалоги, листы, сцены интеграций),
   из `docs/frontend.md` → «Каталог состояний» и из клиента. Каждое состояние — с рецептом,
   как его открыть (скрипт Playwright или подмена снимка через `page.route`, как
   `web/.local/durak-six.mjs`).
   **Готово:** `docs/screens.md` с таблицей экранов и рецептов.

2. **Съёмка.** Скрипт снимает все экраны на 320/390/768/1024/1280/1440/1920 в обеих темах и
   при масштабе 200 %, в `backlog/screens/catalog/<экран>/<ширина>-<тема>.png`.

3. **Аудит чёткости.** Для каждого снимка автоматически: горизонтальное переполнение,
   элементы за краем, обрезанный текст (`scrollWidth > clientWidth` у текстовых узлов),
   наложения (`elementFromPoint`), размытые растровые иконки (размер картинки меньше размера
   на экране × DPR), дробные пиксели у тонких линий, контраст. Глазами — субагентом по
   скриншотам. Найденное — исправить, повторно снять.
   **Готово:** отчёт с числами «найдено → исправлено» по каждому классу.

4. **Figma.** Авторизация MCP-сервера Figma — шаг владельца (`OWNER-ACTIONS.md`). Если
   доступ есть — по документации MCP на дату работы занести экраны в файл владельца, по
   странице на раздел, с компонентами из E16, если MCP позволяет писать. Если писать нельзя
   — html.to.design или импорт картинок с подписями. Нет доступа — подготовить всё для
   импорта (`screens/catalog/` + HTML-страницы экранов) и инструкцию в два шага.
   **Готово:** ссылка на файл Figma в журнале или пакет импорта с инструкцией в
   `OWNER-ACTIONS.md`.
