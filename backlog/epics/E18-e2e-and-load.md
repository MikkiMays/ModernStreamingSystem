# E18 — Полный прогон e2e и нагрузка

Выделен владельцем 20.10.2026 из основного потока: «Нагрузочное и проверки оставь как невыполненный эпик и убери из
этого стрима… она будет выполнена позже». Состояние — **ждёт**; в этой сессии не делается.

## Задачи владельца

- **T09** — «Отказоустойчивость, нагрузка на сервер при видео и стриминге» (перенесена сюда из E05).

## Что сделать

1. **Полный прогон e2e против стенда за один заход.** Набор создаёт ~60 встреч с одного адреса, а антибот разрешает
   `ABUSE_IP_ROOMS_CREATED=10 per hour` (и `ABUSE_IP_OPEN_ROOMS`). Нужно решение владельца: поднять пределы на время
   прогона (сам владелец или правило разрешения в Claude Code — классификатор агента это запрещает) или гонять порциями
   по часу (`backlog/knowledge/memory/cord-e2e-create-budget.md`). Список ни разу не прогнанных спеков и спеков «после
   выкатки» — `backlog/journal/2026-10-20-quality-wave.md`. Сценарии кинозала и музыки — проверить после T59 (новый вход
   с выбором площадки; `web/e2e/support/cinema.ts` писался под старый).
2. **Нагрузка (T09):** 20 человек во встрече (WP1 — до 20 людей, SFU +4), показ экрана 1080p60 + камеры, кинозал и
   музыка одновременно; замеры CPU/RAM/сети ядра, SFU и служб; восстановление при обрыве сети (E05 T50) под нагрузкой.
3. **Нагрузочный сценарий антибота** (`docs/abuse-model.md`): скрипт создаёт встречи, пока человек создаёт свою.
4. **CI `browser` на Windows:** 39 из 63 сценариев красные — пределы по IP и `ECONNREFUSED 127.0.0.1:18100` (службы не
   подняты на раннере) — см. журнал волны качества.
5. **Время решения PoW на слабом телефоне** (стоимость 50 000 — оценка).
6. Живые проверки, которые возможны только на машине с Windows: обновление Electron N−1→N, звук системы, клавиши поверх
   игр, установщик (журнал E01-B).
