# E00 — Изучение системы и фундамент работы

Владелец: «стоит полностью изучить систему прежде чем приступать к прочтению десятков
задач», «а также чтобы сам создавал скиллы и использовал» (T28).

Этот эпик ничего не меняет в продукте. Его результат — точная карта системы, проверенный
исходный уровень и инструменты, которыми пользуются все следующие эпики.

## Шаги

0. **Сервер.** `CONTEXT.md` → «Сервер — это прод»: `$CORD_ROOT`, инструменты, доступ к
   GitHub, ресурсы, поднят ли здесь прод. Итог — `journal/ENV-<hostname>.md`. Переезд прода
   на эту машину — эпик E17, следующий после E00.

1. **Исходный уровень.** Обе репы: ветки, `origin` против локального `main`, незакоммиченное,
   старые worktree, если есть.
   CI: последние прогоны `main` обеих реп. Прод: `docker compose ps` против HEAD, «О программе»
   на https://meet.nikg.tech, `curl` к `/api/v1/ping`. Последний релиз Windows и зеркало
   `/download`.
   **Готово:** таблица «что где лежит и чем отличается» в `journal/<дата>-E00.md`.

2. **Чтение.** Всё из «Обязательного чтения» `CONTEXT.md`: доки обеих реп, прошлые
   спецификации и планы. Затем пройти код по слоям: ядро (`room`, `game`,
   `api`, `access`, `media`), веб (`core`, `media`, `ui`), службы, Windows. Где удобнее
   субагенты (`Explore`, `feature-dev:code-explorer`) — дай им непересекающиеся слои.
   **Готово:** `CONTEXT.md` сверен с кодом, неверное исправлено. Для каждого эпика в
   `journal/<дата>-E00.md` записаны точки входа, которых в эпике не хватает. Если они
   существенны — допиши их в сам файл эпика.

3. **Прогон проверок.** Один полный прогон, чтобы знать исходное состояние: веб (`npm test`,
   `tsc -b`, `format:check`, `build`), ядро (`fmt:check verify` в контейнере), службы, e2e
   против прода (`meeting`, `screens`, `connect`), Windows-проверки на Linux.
   **Готово:** у каждой проверки записаны код выхода и время. Падающее до начала работ
   отмечено как исходное, а не «сломали мы».

4. **Инструменты для всех эпиков** — в `backlog/bin/`:
   - `active-meetings.sh` — есть ли сейчас живые встречи (LiveKit `lk room list` или запрос
     к ядру/БД). Выход 0 — пусто, 1 — идут встречи, со списком. Нужен перед каждой сборкой
     на проде.
   - `deploy.sh <служба…>` — `active-meetings` → `flock .deploy.lock` → `compose build` →
     `up -d --no-deps` → ожидание healthy → сверка образа с HEAD. Без `down`, без `-v`.
   - `ci-status.sh` — последние прогоны CI обеих реп (`gh` или REST с токеном из окружения).
   - В `.github/workflows/verify.yml` — `paths-ignore: ['backlog/**']` для `push` и
     `pull_request`: коммит, меняющий только бэклог, не гоняет весь CI.
   - `shots.mjs` (в `web/.local/`) — скриншоты экрана по списку ширин и тем, «до» и «после».
   **Готово:** каждый скрипт один раз прогнан, вывод — в журнале.

5. **Скиллы для Claude** в `ModernStreamingSystem/.claude/skills/`, по
   `superpowers:writing-skills` и `mattpocock-skills:writing-for-agents`. Минимальный набор:
   `cord-deploy` (выкатка и проверка), `cord-verify-ui` (скриншоты, ширины, темы,
   переполнение), `cord-live-call` (два браузера против прода/стенда, getStats),
   `cord-server-tests` (maven в контейнере, fmt, fork). Существующий `web/.claude/skills/verify`
   не дублировать — сослаться на него.
   **Готово:** каждый скилл использован хотя бы раз на настоящей задаче E00 (например,
   `cord-verify-ui` снимает исходные скриншоты главной, встречи и настроек в
   `screens/E00/`). Закоммичено в `main` (докам и скиллам выкатка не нужна).

6. **Инструменты извне.** Проверь, что доступны плагины и MCP из `README.md` → «Что
   подключить» (Playwright, context7, веб-поиск, Figma). Не хватает — поставь
   (`claude plugin install …`); авторизацию, которую делает только человек, запиши в
   `OWNER-ACTIONS.md`. Звуки
   (E08) — проверь, какие MCP или скиллы для генерации/подбора звука существуют, и запиши
   находки в `DECISIONS.md`.

## Чего здесь не делать

Никаких правок продукта: ни кода, ни конфигурации прода. Найденный по дороге баг — в журнал
и в подходящий эпик.
