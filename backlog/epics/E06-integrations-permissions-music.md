# E06 — Права интеграций, музыка, витрина

Этап A (права) — волна 1. Этап B (музыка, витрина, SOON) — волна 3, после E16.

## Задачи владельца

- T14 «Убирать музыку из интеграций должен уметь каждый, если включена возможность управления
  интеграциями, если даже не владелец встречи, сейчас любой зритель не может. Проработка
  пермиссий, в целом проверь и если что зарефактори»
- T18 «Думаю стоит чуть переделать интеграцию музыки. Возможно добавить другие, либо
  переделать, ну если есть возможность например добавлять другие или мб нет смысла.
  Переработка интерфейса короче»
- T30 «Интеграция с телеграмом снести в самый низ интеграций, подключить может только человек
  создавший встречу, пока что оставить в SOON»
- T08 «Интеграции - “любая игра” SOON»
- T12 «Сцена стендап - как отдельная интеграция - SOON»
- T13 «Доска рисования для всех участников в лайве, как отдельный тип интеграции - SOON»

## Что уже есть

- Причина T14 найдена при подготовке: `services/cord_services/app.py` — `DELETE
  /api/v1/services/rooms/{room_id}/music` требует `core.member(..., owner=True)`, тогда как
  включение, команды и загрузка — `integration=True`. В ядре правило «ведущий или
  `integrationsAllowed`» — `RoomService.java:1107`; в вебе — `canUse` в `ui/Services.tsx:112`.
  Правило живёт минимум в трёх местах.
- Взаимоисключения интеграций («сцена» и «уши») — `Services.tsx` (`RIVALS`) и проверки в
  ядре и службе.
- Музыка: `services/cord_services/music.py`, `yandex.py`, Go-издатель стерео, UI —
  `ui/MusicPlayer.tsx`, `MusicQueue.tsx`, `MusicUpload.tsx`, `YandexIntegration.tsx`;
  `docs/INTEGRATIONS.md`. Уже есть yt-dlp (кинозал) — им можно брать звук с YouTube/SoundCloud.

## Этап A — права (T14)

1. Выписать **все** действия всех интеграций (музыка, кинозал, покер, дурак, шахматы, Gartic,
   Telegram, Яндекс-аккаунт, настройки встречи) и кто их сейчас может — по коду ядра, службы и
   веба, с `путь:строка`. Таблица — в спецификации.
2. Одна матрица прав в ядре: роль (создатель/ведущий, участник, ожидающий, бот) × флаг
   встречи `integrationsAllowed` × действие. Ядро отдаёт в снимке участника готовый набор
   `you.can` (как `you.actions` у покера). Служба спрашивает ядро по имени действия, веб
   читает `you.can`. Своих копий правила нет ни в вебе, ни в службе.
3. Исправить по матрице: убрать музыку может каждый, кому разрешены интеграции (T14);
   Telegram-привязка — только создатель (T30); остальные расхождения — по таблице, с
   объяснением.
4. Тест-матрица: ядро — параметризованный тест по таблице; служба — тест на каждый маршрут;
   e2e — участник без прав ведущего убирает музыку.

**Готово:** таблица «было → стало» по каждому действию; ни одной проверки прав вне матрицы
(`grep` по `owner=True`, `.owner`, `integrationsAllowed` с разбором каждого вхождения).

## Этап B — музыка и витрина (T18, T30, T08, T12, T13)

1. **Музыка (T18).** Сначала исследование: какие источники можно добавить законно и без ключей
   через уже имеющиеся инструменты (YouTube, SoundCloud, Rutube через yt-dlp; ссылка на файл;
   радио по потоку) и стоят ли они того. Решение и причина — в `DECISIONS.md`. Затем
   интерфейс на дизайн-системе E16: карточка «сейчас играет» с обложкой и прогрессом, очередь
   с перетаскиванием, единый поиск по источникам, добавление по ссылке, громкость слушателя
   рядом (T49 — E05).
2. **Витрина (T30, T08, T12, T13).** Порядок групп: игры, кинозал, музыка, …, Telegram — **в
   самом низу**. Бейдж SOON (примитив E16) у «Telegram», «Любая игра», «Сцена стендап»,
   «Доска рисования». Карточка SOON не нажимается как действие, а показывает одну строку «что
   это будет». Telegram-карточку видит каждый, но подсказка «подключит создатель встречи» — у
   всех, кроме создателя.
3. Записать в спецификации короткие замыслы трёх SOON-интеграций (стендап — сцена одного
   выступающего со зрителями; доска — общий холст в реальном времени, можно строить на
   холсте Gartic; «любая игра» — что это значит технически), чтобы следующему эпику было с
   чего начать. Код этих интеграций — не делать.

**Готово:** скриншоты витрины и музыки до/после; e2e музыки зелёные; каждый новый источник
музыки — живой прогон в комнате.
