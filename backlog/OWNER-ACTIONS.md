## Перед запуском на новом сервере

`README.md` → «Новый сервер» — команды по порядку. Только владелец может:

- **Войти в Claude Code** (`claude`, затем `/login`, аккаунт с планом Max) и в GitHub
  (`gh auth login` или токен с доступом к обеим приватным репам, правами `contents`,
  `actions`, `workflows`; для релиза Windows — ещё запись релизов).
- **Новый сервер — прод (решено 18.10.2026).** Для переезда (E17) владелец даёт:
  `.env` и `youtube_cookies.txt` со старого сервера (положить в `ModernStreamingSystem/`, в git
  их нет и не будет); дамп PostgreSQL старого прода или SSH-доступ к старому серверу —
  иначе старт с чистой базой и избранное людей пропадёт; переключение DNS `meet.nikg.tech` на
  новый IP (или доступ к DNS).
- **Режим без подтверждений.** Под root Claude Code отказывается работать с
  `bypassPermissions`. Нужен либо отдельный пользователь (в группе `docker`), либо режим
  `auto` (по умолчанию в `bin/run.sh`).

## Действия, которые агент не может сделать сам

- **Figma (E15, E16; T57):** подключить MCP-сервер Figma и авторизовать его (OAuth в
  браузере) — `README.md` → «Что подключить». Создать файл «Cord» и дать ссылку. Если MCP не
  умеет рисовать на холсте, агент напишет плагин Figma — его нужно будет один раз запустить в
  этом файле (Plugins → Development → Import plugin from manifest). Без доступа E15 готовит всё
  к импорту и не стоит.
- **Telegram (E09):** код готов и выключен (`TELEGRAM_WEBAPP_ENABLED=false`). Чтобы включить — BotFather:
  Configure Mini App → Enable Mini App с адресом `https://<домен>/tg`, Splash Screen цветом `#111419` для
  обеих тем, по желанию Description Picture; затем флаг в `.local/telegram.env` и перезапуск `services`
  (`docs/deployment.md` → «Telegram Mini App»). `/setdomain` не нужен. Проверка на телефоне — iOS и Android:
  камера и микрофон внутри Telegram, полный экран, закреп кнопки в группе и в теме форума.
- **Мобильные приложения (E12), если E12 решит, что без нативной оболочки нельзя:** Apple
  Developer Program ($99/год), Google Play Console ($25 разово).
- **Подпись Windows-установщика / Electron (E01):** сертификат издателя (или Azure Trusted
  Signing). Без него SmartScreen остаётся (это уже так) — для «продукта» это первое, что
  видит человек, поэтому стоит сделать к выпуску Electron-клиента.
- **Платные сервисы:** любые — только с его «да» (E10, E11).

### 25.10.2026 — W1b надёжность: хост (R10, `docs/deployment.md` → «Хост»)

Контейнеры к настройкам хоста не допущены; агент хост не трогал. На машине стенда (и на будущем проде), под root:

1. **Swap не для медиа:** `printf 'vm.swappiness = 10\n' > /etc/sysctl.d/90-cord.conf && sysctl --system`. Сейчас 60: ядро Linux уводит страницы SFU и издателя в swap при свободной памяти, а страница в swap — это пакет с опозданием. И не держать на машине `vite dev`, `tsserver`, LSP (замер MEDIA-DIAGNOSIS §6: 1,0 + 1,0 + 1,6 ГБ).
2. **Счёт замираний в метрику:** `install -m 0755 /opt/ModernStreamingSystem/infra/host/soft-lockups.sh /usr/local/sbin/cord-soft-lockups && echo '*/5 * * * * root /usr/local/sbin/cord-soft-lockups' > /etc/cron.d/cord-soft-lockups`. Скрипт пишет `/var/lib/node_exporter/textfile/cord_host.prom` (каталог смонтирован в `node-exporter`); метры `cord_host_soft_lockups_total`, `…_day`, алерт `HostSoftLockups`, панель на «Cord — медиа». По ним сравнивать до/после смены тарифа.
3. **Дренаж при выкатке требует `ADMIN_PASSWORD` в `.env`** (страница «Активность» уже на нём): без него `deploy.sh --drain` откажет, останется прежний ручной порядок с `ADMISSION_OPEN`.
4. **Выделенные ядра (dedicated vCPU)** — решение по тарифу/хостеру из п. 5 выше остаётся: куратор (`cord_probe_loss_ratio{leg="down"}` на машине без сети между участниками) теперь покажет вклад хоста числом — после выкатки сравнить его показания в тихий час и в час соседской нагрузки.
