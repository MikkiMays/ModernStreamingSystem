С 20.09.2026 в [[meet-cord-system]] сроки хранения собраны в `stream.retention`
(`server/src/main/resources/application.yml`) и пишутся **словами**, а не секундами:

- `saved-room` (`7 days`) — сохранённая в избранное встреча без единого входа;
- `unsaved-room` (`immediately`) — завершённая встреча, которую никто себе не сохранил;
- `closed-history` (`1 hour`) — переписка и события после завершения;
- `messages` (`1 day`) — сообщения, расписки, приглашения и вложения идущей встречи.

Разбирает их `config/Term.java`: `7 days`, `2 weeks`, `3 months`, `month`, `90m`, `never`,
`immediately`; окончание `s` необязательно. **`m` — это минуты**, месяц только `mo`/`month`.
«Никогда» — это сто лет (`Term.FOREVER`), чтобы ни одно сравнение времени не обзаводилось
веткой про `null`. Непонятная строка роняет старт — так и задумано. В Spring это попадает
через `TermConverter` (`@ConfigurationPropertiesBinding`), то есть строки в `Duration`
превращаются только при разборе настроек.

**Главная перемена в поведении:** несохранённая встреча удаляется тем же проходом уборки,
который её закрывает, — без прежнего часа ожидания. Это же значение задаёт окно на «я
случайно вышел»: пока оно не истекло, встреча открывается по ссылке из списка недавних.
Кому нужен запас — `unsaved-room: 1 hour`.

Из-за этого пришлось чинить три теста в `RoomServiceTest`: комнате, которую проверяют
после закрытия, теперь нужен `saved(...)` — иначе её уже нет.
