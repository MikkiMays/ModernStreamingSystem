`/opt/meet` — это **Cord**, приложение для видеовстреч. Не путать с [[kiki-jarvis-system]]:
это отдельный продукт, живущий на той же машине.

Два независимых git-репозитория (оба приватные у MikkiMays, на 15.09.2026):

- `ModernStreamingSystem` — ядро (Java 25 / Spring Boot), веб (React 19 / Vite), сервисы
  (Python, музыка и Telegram), инфраструктура. Прод: https://meet.nikg.tech
- `ModernStreamingSystem.Windows` — клиент Cord (C# / .NET 10 / WinUI 3). Разговор идёт
  внутри WebView2 через тот же веб-клиент, поэтому UI-правки едут с сайта, а не через EXE.

Собрать и проверить клиента можно и здесь, не всё: [[windows-client-checks-on-linux]].

Медиа — LiveKit SFU, host networking, всё поднимается одним `docker compose` из корня
`ModernStreamingSystem`.

**Три режима установки** (15.09.2026), выбираются `setup.sh`:

- `simple` — одно DNS-имя. TURN/TLS на 5349, сертификат держит сам LiveKit.
- `strict` — три имени (app/rtc/turn), TURN поверх 443 по SNI. Прежнее поведение; прод
  сейчас именно такой.
- `ip` — без DNS, самоподписанный сертификат с IP в SAN.

Приложение и signaling разделены по путям (`/rtc` идёт на LiveKit), поэтому отдельное имя
для rtc нужно только в strict. Почему нельзя иначе — [[livekit-turn-and-secure-context]].

**Вход на сервер** (с 15.09.2026): Cord открывается на экране подключения, а не на списке
комнат. `ACCESS_PASSWORD` в `.env` пуст по умолчанию — сервер открыт, как и раньше; со
значением `POST /api/v1/session` меняет пароль на подписанный токен, а `RequestGuard` закрывает
`/api/v1/**` кроме `ping`, `capabilities`, `session` и `events`. На проде пароль **не** включён.

**Сервера по умолчанию у клиента нет** (с 19.09.2026, выпуск 0.7.3). Свежая установка не знает
ни одного адреса: первый запуск показывает пустой список и подсказку «впишите адрес того
сервера, с которого скачали Cord»; ту же строку печатает установщик, а страница `/download`
пишет свой `location.origin` с кнопкой «Скопировать». Пустой `ServerUrl` — законное состояние,
и `ProfileStore` на нём не падает. Приёмке выпуска адрес называют снаружи
(`--verify-service <адрес>`), а профиль ей готовит `scripts/verify-service.ps1`.

**Раздача клиента** (с 15.09.2026): `<адрес>/download` отдаёт установщик Windows с самого
сервера, из `.local/windows-releases`; кладёт туда `scripts/publish-windows-release.py`.
Установщик **не подписан**, и убрать предупреждение SmartScreen изнутри нельзя — ни правами
администратора, ни метаданными. Дешёвый путь (Microsoft Artifact Signing, $9.99/мес) закрыт
для индивидуальных разработчиков вне США и Канады — это записано в инструкции Microsoft.
Сборка к подписи готова: `scripts/sign.ps1` ничего не делает без секрета `CORD_SIGN_PFX_BASE64`.

Выкатка: править working tree → `docker compose build <служба>` → `docker compose up -d
--no-deps <служба>`. Веб собирается **внутрь образа gateway**, поэтому правки интерфейса
требуют пересборки именно gateway, а не core. Кинозал, музыка и Telegram — это `services`, а
**проверки ядра** (аватар, комнаты, команды) — `core`: забыть про него легко, и выглядит это
как «починил, а всё равно не работает» — прод продолжает отвечать старым отказом. Образ `services` с 15.09.2026 собирается в два
шага: сначала Go собирает издателя звука ([[livekit-stereo-only-via-go]]), потом Python. Первая
сборка — минут пять-десять, дальше слои из кэша; запускать её в фоне, `timeout` её убивает.

**JDK на хосте нет.** `./mvnw` падает на JAVA_HOME. Серверные тесты и `fmt:format` гонять в
контейнере: `docker run --rm -v cord-m2:/root/.m2 -v /opt/meet/ModernStreamingSystem:/w -w /w
maven:3.9.11-eclipse-temurin-25 mvn -B -pl server test`. Том `cord-m2` уже прогрет, прогон
~1.5 минуты. `Dockerfile.server` собирается с `-DskipTests`, то есть сборка образа ничего не
проверяет. CI дополнительно требует `fmt:check` — форматтер правит отступы иначе, чем кажется.

**Никогда не делать `docker compose down -v`** — это сносит тома с базой и файлами.
