Жалоба 23.09.2026: «нажимаешь обновить, полоска идёт, приложение перезапускается — версия
прежняя». Корень доказать отсюда нельзя (журнал на машине владельца:
`%LOCALAPPDATA%\Cord\updates\installer.log`, с 0.7.5 ещё `update.log` и `result-last.json`),
но путь был заведомо дырявый, и документация сама признавала: «занятые файлы и переход между
двумя релизами требуют отдельной приёмки» — то есть именно этот путь не проверялся никогда.

Что было не так в [[meet-cord-system]] (клиент `ModernStreamingSystem.Windows`):
- помощник `Update.ps1` ждал **один** процесс; второе окно Cord или процесс, закрывший окно
  и не вышедший, держали файлы — установщик отказывал, Cord перезапускался старым;
- причина стиралась при следующем запуске и показывалась как «Соединение»;
- успех установщика принимался по коду выхода, версию на диске никто не сверял.

С 0.7.5: убирает всё, что запущено из каталога установки, добивает свой зависший процесс
через 30 с, повторяет установку один раз, сверяет `FileVersion` у `Cord.exe` (у apphost он
есть: `0.7.4.0`; `ProductVersion` с хвостом `+sha`), пишет `update.log`, итог показывает
плашкой «Обновление». **Переход на 0.7.5 делает ещё старый помощник** — если не встанет,
владелец ставит 0.7.5 вручную один раз.

Грабли: помощник обязан быть **ASCII** (PowerShell 5.1 читает файл без BOM в ANSI). Разбор
скриптов здесь — портативный pwsh в скретчпаде (`github.com/PowerShell/PowerShell` releases,
linux-x64.tar.gz, 7.6.6 работает) + `[System.Management.Automation.Language.Parser]::ParseFile`.
CI гоняет `scripts/test-installer.ps1` с настоящим установщиком и «лишним» Cord из каталога.
