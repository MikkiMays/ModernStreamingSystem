Сделано 20.10.2026 в E12 (T16) в [[meet-cord-system]]. Разбор платформ — `docs/mobile.md`, сделанное —
там же §7–§9. Продолжение [[cord-call-in-pocket]].

**Держит разговор только захват микрофона** (Android Chrome — свой FGS, Safari — аудиосессия), а
приложение Cord для Android — свой FGS `microphone` (`mobile/`, плагин `CordCall`). Wake Lock держит
экран, а не процесс: включается только для видео, iPhone «Домой» и телефона без захвата.

**Грабли.**
- `livekit-client` 2.22 на телефоне через 5 с в фоне ставит камере `enabled = false`, а по возвращении
  поднимает её перезапуском (`needsReAcquisition` смотрит на `enabled`). Не «чинить» это своим кодом.
- SDK создаёт `AudioContext` на каждое подключение и закрывает при обрыве: после полного переподключения
  новый рождается без жеста и на iOS молчит. Поэтому контекст свой (`webAudioMix: { audioContext }`):
  SDK закрывает только свои — закрывать наш должен `MediaSession.dispose`.
- `resume()` контекста без жеста в Safari не отказывает, а **висит** — ждать с таймаутом (`AudioWaker`).
- Safari не шлёт `freeze`: заморозку видно только по перерыву в тиках таймера (`PageLifecycle`, ≥ 10 с).
  После заморозки сигнальный сокет SDK мёртв, а SDK считает его живым до таймаута пинга — толкать `resume`.
- `pagehide` без `persisted` на телефоне приходит и при переключении приложений — выход из встречи на нём
  не слать. Маяк встречи (`core/active-meeting.ts`) по `persisted` только «уходит» и по `pageshow` возвращается.
- Заглушённую дорожку публиковать **после** `mute()`: в запросе публикации уходит `muted`, и сервер ни
  мгновения не считает микрофон включённым. После полного переподключения выключенный захват публиковать
  снова — иначе «включить» захватит второй раз и первый будет гореть до конца встречи.
- Страница в оболочке Capacitor получает мост `window.Capacitor` без `@capacitor/core`: хватает
  `isNativePlatform`, `nativePromise`, `addListener` (`core/mobile-app.ts`). `startForegroundService` из фона
  на Android 12+ запрещён — уведомление обновлять через `NotificationManager.notify`.
