# R207: админ-панель и служба `fleet` — журнал (08.11.2026)

Ветка `release/r207-admin` от `release/r200-impl` + слияния `origin/release/1.2`. Агент Fable, один. Проект —
`docs/architecture/admin-panel.md` (Р-111…Р-120), вопросы владельцу — `OWNER-ACTIONS.md` п. 21. Правила сессии:
никаких выкаток и подключений к meet/cordcam/B — всё проверялось против локального ядра стенда A и фейков.

## Сделано

- **B1 проект.** Пользователи и угрозы, вход (пароль scrypt + TOTP, allowlist, кука `__Host-fleet`, CSRF), журнал,
  архитектура (Compose + реестр + пульт; k8s — когда и почему нет, §3.1), каталог операций → `argv`, экраны с макетами и
  состояниями, источники данных, предохранители, бэклог B1–B16.
- **B2 служба `fleet`** (`services/fleet/`, FastAPI, SQLite, свой образ с `openssh-client`): `settings`, `store`
  (сессии, попытки входа, журнал только на добавление, задачи и строки вывода), `auth` (scrypt с `maxmem` — OpenSSL по
  умолчанию режет 32 МиБ; TOTP с окном ±1 шаг, вектор RFC 6238 в тесте), `machines` (`FLEET_MACHINES`, учётные данные
  ядра — отдельно в `FLEET_CORE_<ID>`), `core_link` (вход паролем для стенда или `fleet.<ключ>` для продукта),
  `catalog` (14 операций; имя узла, ветка, служба — по шаблону или перечню), `executor` (`DryRun` по умолчанию,
  `Fake` для тестов, `Ssh` за `FLEET_EXECUTOR=ssh` + `FLEET_SSH_MACHINES`; одна задача на машину; отмена — SIGINT),
  `metrics` (VictoriaMetrics/vmalert; без профиля — честная ошибка в плашке), `app` (`/api/fleet/*`). 50 тестов,
  CI-шаг в `deployment-config` (образ `--target test`, `--network none`). `scripts/fleet-setup.mjs` пишет
  `.local/fleet.env`. Профиль compose `admin`, том `fleet-data`, ключи `/keys:ro`.
- **B3 шлюз и имя.** `infra/Caddyfile`: блок `@admin host {$ADMIN_HOST:admin.invalid}` — `admin.html` и
  `/api/fleet/*` → 127.0.0.1:18200, `X-Real-IP`, срез `X-Fleet-Agent`; на имени приложения `/admin.html` → 404.
  `edge-config.mjs --admin` (четвёртое имя, только strict), `configure.mjs --admin` и `--refresh --admin` → `ADMIN_HOST`
  в `.env`; `csp-check.sh` проверяет имя пульта. Тесты node и bash.
- **B4–B9, B11 (журнал) веб.** `web/admin.html` → `web/src/admin/`: вход, каркас (навигация, машина-контекст, плашка
  «СУХОЙ ПРОГОН / ВЖИВУЮ»), Обзор, Тех. работы (R194 + дренаж), Встречи (сейчас/за период, завершить с блоком создателя),
  Узлы (дренаж/снять, проверить, журнал, обновить, удалить с именем; «Добавить сервер» → DNS-записи и точные команды
  `node-config.mjs`/`node.sh`), Выкатки/откаты, Задачи (живой вывод опросом `after=N`, отмена, повтор), Журнал
  (пульт с фильтрами и JSONL, ядро, сессии с «выйти везде»). Разделы Безопасность/Ошибки/Метрики/Флаги/Выпуски —
  честные заглушки со ссылкой на пункт бэклога. Тексты — `web/src/i18n/admin/ru.ts` (Р-114). 6 тестов vitest.
- **B5 ядро.** `FLEET_KEY` → `AdminAccess.valid("fleet.<ключ>")`; без пароля владельца вход паролем — 404 как раньше.

## Проверено

- `services/fleet`: 50 unittest в образе; `scripts/*.test.mjs` (edge, configure, fleet-setup); `csp-check.sh` с образом
  Caddy; `docker compose --profile admin config`; `tsc -b`, `npm run build` (три входа), vitest `src/admin`,
  `format:check`, храповик кириллицы без роста; ядро — `OwnerAccessTest`, `ActivityTest` в Maven-контейнере.
- Дымовая проверка службы на A против живого ядра стенда (контейнер на 127.0.0.1:18201 с одноразовым
  `.local/fleet.env`, затем удалён): вход паролем+кодом, отказ с одной ошибкой, `overview` читает `now` и окно работ
  стенда, задача `deploy` в сухом прогоне печатает план, живая задача отказана `EXECUTOR_DISABLED`, план «Добавить
  сервер» для `hel`, журнал пишет всё. `GET /api/v1/nodes` на стенде ответил 404 — на стенде ещё нет кода R200 8.1;
  экран «Узлы» это показывает, не падает.

## Не сделано / решает владелец

- `SshExecutor` против настоящих машин не запускался (правило сессии); включение — `fleet-setup.mjs --executor=ssh
  --ssh-machines=…` после ответа на п. 21 `OWNER-ACTIONS.md`. Туннель SSH к ядру meet (B10) — не написан: `CoreLink`
  ждёт локальный адрес, который даст `ssh -N -L`; сам туннель — отдельная единица (systemd на A или sidecar в compose).
- B11 (безопасность, ошибки/обращения), B12–B16 — заглушки или в бэклоге; `node-config.mjs --remove` и
  `active-meetings.sh --wait` (в плане `node.update`) — ещё не существуют (B15), сухой прогон их показывает, живой
  исполнитель на них споткнётся — это намеренно: план виден, прежде чем он станет кодом.
- Выкатка пульта на A (`--admin=admin.callcord.ru`, профиль `admin`, `FLEET_KEY` на meet) — не делалась.
