## R123 — переключатели

**Корень.** (1) Зазор 2 px на 125 % — 2,5 физических пикселя; Chromium прижимает к пикселю каждый край
отдельно, и на дробной позиции дорожки плашка выходит 2 сверху и 3 снизу (на всех переключателях).
(2) Плашка вкладок — `Tabs.Indicator` Base UI: смещение от `clientLeft` (целый CSS-пиксель) через
`translate`; сегмент — `offsetLeft`/`offsetWidth` (целые) через `transform`: слева и справа 1–3 против 3.
(3) В тёмной теме плашка вкладок `--surface-1` темнее дорожки `--surface-2` («вдавленная»), у сегмента —
`--surface-3`. (4) Выбранная вкладка Base UI 1.8 — `aria-selected`/`data-active`, а не `data-selected`:
подпись выбранной не подсвечивалась. (5) В панели 320 px вкладки «Люди 1 · Чат и файлы · Интеграции» не
сжимались и вылезали за дорожку на 24 px (фото 08).

**Сделано.** `ui/device-pixel.ts` (`--device-px`), токен `--tab-gap = round(2px → целое число физ.
пикселей)` (2,4 px на 125 %); зазор — полем дорожки (рамку Chromium округляет до CSS-пикселя: 2,4 → 2);
`kit/usePlate.ts` — плашка `left`/`width` по прямоугольнику пункта на сетке 1/64 физ. пикселя, общий для
`Tabs` и `Segmented`; плашка `--surface-3` + `--shadow-1`, радиус = радиус дорожки − зазор; вкладки в
дорожке `flex: 1 1 auto; min-width: 0` с многоточием подписи; линзы камеры — тот же зазор.

**Замер** (`switcher-gaps`, DPR 1 / 1,25 / 1,5, обе темы): `/kit` со стенда — **40 кривых из 81**
(125 %: сверху/снизу 2/3 везде; 150 %: справа 1–2 против 3; тёмные вкладки темнее дорожки); после —
**0 из 108** (с 175 %). Настоящие места после: панель 320/360 — 0/36, «Поддержка» (вкладки и «Написать
нам | Сообщить о проблеме») — 0/48, «Что показать» — 0/30, настройки «Видео» — 0/48, «Оверлей» — 0/60.
Переполнение панели 320: было «дорожка шире на 24», стало 0 (`after/harness/report.json`).

## R122 — кнопки окна поверх шапки

**Корень (насколько видно без Windows).** На фото «☐» (окно не развёрнуто, 01) — поле справа есть, «⧉»
(развёрнуто, 03/04/08) — звезда, ссылка и гарнитура под «— ⧉ ×»: зона Window Controls Overlay пришла пустой
(или во всю ширину), `--titlebar-end` = 0. В Electron 44.4+ зона идёт к странице новым путём
`WebContentsView::SendWindowControlsOverlay` (перевод в координаты вида, обрезка, синхронная отправка в
`OnContentsBoundsChanging` — electron#53811), который уже ломал окна с `titleBarOverlay` (#54025). Исходники
Electron 44.9.1 (`win_frame_view.cc`, `electron_api_web_contents_view.cc`) прочитаны; точный шаг, на котором
развёрнутое окно получает пустую зону, без живого Windows не пойман.

**Сделано (веб, без релиза клиента).** `core/titlebar.ts`: в клиенте Windows (мост v2 + Windows в строке
браузера) поле и высота полосы не меньше самих кнопок — 137×36 DIP (`WinCaptionButton`: 45 + 46 + 46) с
поправкой на масштаб страницы; пересчёт и по `geometrychange`, и по `resize`/`fullscreenchange`; во весь
экран — нули; `data-titlebar` на `<html>`. Вертикаль: шапки встречи и предвхода в клиенте — заголовок окна
высотой полосы (36), кнопки 32 на одной линии с «— ⧉ ×», как у Discord/VS Code (раньше на 10 px ниже).
Диалоги и настройки и так опускаются на `--titlebar-h` — теперь он не ноль и в развёрнутом окне.

**Доказательство.** `vitest src/core/titlebar.test.ts` — 11 (RED → GREEN: пустая зона, зона во всю ширину,
развёртывание без `geometrychange`, полный экран, масштаб 0,8/1,25). `titlebar-shots` на 125 %: стенд, зона
пустая — встреча: 3 кнопки шапки под кнопками окна (как на фото), предвход: «На главную»; после — 0 из 9
(пустая / видимая / во всю ширину).
