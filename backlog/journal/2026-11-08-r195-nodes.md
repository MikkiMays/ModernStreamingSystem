## Сквозная проверка на B (временное ядро + база + веб на самом B, два headless Chrome 124 на B)

Реестр для теста: `fra` (control) = второй LiveKit на B (`ws://127.0.0.1:7890`), `hel` = настоящий узел B через edge и
gateway-lite с `forward_auth` в тестовое ядро.

| Шаг | Результат |
| --- | --- |
| Замер пути (`cord:node:v1`) | `{"node":"hel"}` за < 3 с после открытия главной |
| Ядро: выбор | `room … on node hel (preferred; asked hel; measured [fra: tcp null udp null, hel: tcp 17 мс udp null])` |
| Ведущий: «Начать встречу» → `data-media-status="connected"` | **2079 мс** |
| Гость: «Войти во встречу» → connected | **1327 мс** |
| SFU hel | `livekit_participant_total 2`, пакеты идут в обе стороны |
| `docker compose stop livekit` на узле (T0) | оба клиента `recovering` через **9,4 с**; ядро `did not answer 3 times` и `moved from dead node hel to fra` через **14,6 с**; клиенты «the meeting moved to another media node — reconnecting there»; `connected` у обоих через **15,5–15,6 с**; SFU fra: 2 участника |
| Метрики ядра | `cord_node_up{hel}=0`, `cord_node_choice_total{node="hel",reason="preferred"}=1` |

Побочная находка: после переезда гость дал лишний толчок «входящее молчание» (старый `lastFlowAt`) — исправлено
(`lastFlowAt` и флаг сбрасываются в `connected`). UDP-проба без NAT не даёт `srflx` (Chrome режет кандидат, равный host) —
выбор по TCP, задокументировано в проекте.

После проверки узел возвращён в боевую конфигурацию (`CORE_AUTH_UPSTREAM=127.0.0.1:18080`, `backbone` поднят); тестовая
плоскость `/opt/cord/ctl` остановлена (контейнеры `cord-ctl-*` можно удалить вместе с томом `cord-ctl_db`).
