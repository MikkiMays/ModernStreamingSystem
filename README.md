# ModernStreamingSystem · Cord

Самостоятельное приложение для встреч: аудио, камера, две демонстрации экрана, чат, временные файлы и приглашения по ссылке/QR. Медиа передаёт **LiveKit SFU**, управление — **Java 25 / Spring Boot 4.1.1**, интерфейс — **React 19.2 / TypeScript / Vite 8**.

Исходники ядра, веб-клиента и инфраструктуры находятся в [ModernStreamingSystem](https://github.com/MikkiMays/ModernStreamingSystem). Нативное Windows-приложение развивается отдельно в [ModernStreamingSystem.Windows](https://github.com/MikkiMays/ModernStreamingSystem.Windows); [установщик и переносимая сборка](https://github.com/MikkiMays/ModernStreamingSystem.Windows/releases/latest) доступны в его релизах.

Это работающая первая реализация. Локально проверены реальные соединения браузеров через SFU, шлюз доступа и tusd. Производственная приёмка на европейском VPS, аппаратные 1440p60, TURN/TLS и маршруты реальных пользователей ещё требуют измерений. Точные границы проверки — в [журнале приёмки](docs/verification.md).

## Запустить на Windows

Нужны Java 25 и Node.js 24.11.1. Docker для локального режима не требуется. Из корня проекта:

```powershell
.\scripts\start-local.ps1 -JavaHome 'C:\Java\jdk-25'
```

Открыть **http://localhost:5173**. Создать встречу, ввести имя, скопировать приглашение и открыть его во втором окне браузера. Камера и микрофон включаются пользователем. Для экрана браузер показывает системное окно выбора источника.

Скрипт проверяет контрольные суммы загружаемых LiveKit 1.13.6, tusd 2.10.0 и Caddy 2.11.4, собирает сервер, устанавливает зависимости и запускает процессы в фоне. Логи — `.local/logs/`. При повторном запуске уже занятые порты не перезапускаются.

```powershell
# Повторный запуск после готовой сборки
.\scripts\start-local.ps1 -JavaHome 'C:\Java\jdk-25' -SkipBuild
# Остановить только процессы, запущенные скриптом
.\scripts\stop-local.ps1
```

Перед повторной сборкой JAR на Windows остановите локальный сервер: запущенная JVM удерживает файл. Локальные адреса привязаны к loopback; приглашение `localhost` подходит для браузеров этого компьютера. Для другого устройства, QR с телефона и настоящего TURN используйте HTTPS-развёртывание на VPS.

## Что реализовано

На главной можно ввести девятизначный код в формате `333-333-333` или ссылку. Код отправляет запрос организатору; до подтверждения история, файлы и медиа недоступны. Код и QR находятся в приглашении внутри комнаты. При создании задаются имя пользователя и неизменяемое название встречи. При последующих входах достаточно имени; оно запоминается. Разрешения устройств проверяются на предпросмотре, камера и микрофон остаются выключенными. Устройства, качество и подтверждение входа доступны через шестерёнку в правом нижнем углу предпросмотра.

Кнопка выхода возвращает на главную. Под основными кнопками расположены **до пяти избранных комнат**, сохранённых звёздочкой во встрече. Пока комната есть в избранном хотя бы одного профиля, её название и код не удаляются. Избранное позволяет открыть её снова с сохранёнными правами. Окончание разговора по-прежнему ограничивает срок сообщений и файлов: повторный вход не продлевает старую историю. Настройки качества камеры и экрана (Авто, 720/1080/1440p, 15/30/60 fps), устройства и тема сохраняются. Сообщения и вложения находятся в общей ленте чата.

Каждый зритель может независимо закрепить экран и участника. Лицо ведущего доступно в углу демонстрации или рядом. Автоматическое наблюдение за получаемым потоком отличает статичный экран от зависшего декодирования; при устойчивом накоплении задержки обновляет связанные подписки видео и звука. В диагностике есть ручное «Обновить аудио и видео» с пояснением действия.

В отдельном репозитории [`ModernStreamingSystem.Windows`](https://github.com/MikkiMays/ModernStreamingSystem.Windows) находится **C# / .NET 10 / WinUI 3 приложение**: Mica, системная тема, собственная боковая панель, избранное и постоянный WebView2-профиль. Разговор работает через общий веб-клиент и то же ядро. Установщик, переносимая сборка и команды сборки описаны в его README. Для совместной локальной разработки клонируйте оба репозитория в соседние каталоги с их исходными именами.

- До 10 участников и 2 демонстраций в комнате, атомарное резервирование мест и прав публикации.
- Имя без регистрации, приглашение в URL fragment, QR, отзыв/перевыпуск ссылки, необязательное подтверждение входа, исключение участника, завершение для всех.
- Стабильная идентичность участника, поколения соединения, фиксированный срок восстановления 20 секунд и отдельное восстановление служебного WebSocket.
- Камера 720p30, экран 720p/1080p/1440p × 15/30/60, режимы «Текст»/«Движение», совместимый кодек, simulcast/SVC, адаптивные подписки, диагностика фактических параметров.
- Сохранение пропорций экрана, увеличение, перемещение, полноэкранный режим, сравнение двух источников.
- Идемпотентные команды, ACK, последовательности событий, повторная доставка или полный снимок.
- tus-загрузка с продолжением по offset, паузой при слабом канале, проверкой владельца, квотами и SHA-256; закрытый файловый том.
- Логическое истечение сообщений/файлов сразу по сроку, физическая очистка минутным проходом; недоступное хранилище повторно очищается после восстановления.
- Светлая/тёмная/системная тема, тёмная медиасцена, мобильная панель чата, регулируемая ширина панели на desktop, Base UI и локальные шрифты с кириллицей.
- Docker Compose, Caddy с проверкой каждого внешнего signaling-входа, TURN/TLS на том же TCP 443 через SNI, проверяемые контракты и CI.

1440p60 — запрашиваемый верхний профиль, а не обещание любой сети или любого браузера. Фактическое разрешение/FPS доступны в диагностике. Низкий FPS статичного рабочего стола не считается ошибкой.

Настройки объединены в меню встречи: звук с RNNoise, эхоподавлением, автоматической регулировкой и усилением; камера; имя; горячая клавиша микрофона. Диагностика проверяет микрофон, камеру, динамики и сеть. Громкость каждого собеседника и музыки регулируется отдельно для текущего слушателя. В Windows сочетание микрофона работает и вне окна Cord.

В меню избранной комнаты можно включить автоподключение без предпросмотра: микрофон включён, камера выключена. Создатель управляет доступом участников к интеграциям. [Музыкальный сервис, общая авторизация Яндекс Музыки и 20 команд Telegram-бота](docs/INTEGRATIONS.md) описаны отдельно. [Аудит реальных маршрутов Kiki, Klodi и Fleet](docs/TRANSPORT-2026-09-09.md) объясняет, на какой трафик влияет DNS Only.

## Структура

| Каталог          | Назначение                                                                    |
| ---------------- | ----------------------------------------------------------------------------- |
| `server/`        | Доступ, комнаты, сессии, медиа-права, события, сообщения, вложения            |
| `web/src/core/`  | Управление встречей, независимый WebSocket, deadline восстановления, загрузки |
| `web/src/media/` | Адаптер LiveKit, захват, кодеки/профили, статистика                           |
| `web/src/ui/`    | Главная, предпросмотр, сцена, панели, настройки                               |
| `services/`     | Музыкальный участник, очередь, Яндекс Музыка и Telegram                     |
| `contracts/`     | OpenAPI 3.1 и схема WebSocket-пакетов для веба и C#-клиента                  |
| `infra/`         | Контейнеры, Caddy, локальный SFU, генерируемая конфигурация VPS               |
| `scripts/`       | Воспроизводимый запуск и конфигурация                                         |
| `docs/`          | Архитектура, дизайн, эксплуатация, приёмка                                    |

## Проверить

```powershell
$env:JAVA_HOME = 'C:\Java\jdk-25'
.\mvnw.cmd -B test
cd web
npm ci
npm run format:check
npm test
npm run build
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

Для E2E стенд должен работать. На Linux можно использовать Playwright Chromium после `npx playwright install --with-deps chromium`; Windows-скрипт запуска предусмотрен для локального стенда и Windows CI. PostgreSQL-тесты запускаются через Testcontainers при наличии Docker, иначе явно пропускаются. CI отдельно проверяет, что PostgreSQL-набор не пропущен.

Сгенерировать контракты из работающего локального ядра:

```powershell
cd web
npm run generate:api
```

`web/src/api/generated.ts` генерируется из OpenAPI; транспорт REST и обработка ошибок находятся отдельно в `api/client.ts`. Схема не содержит закрытых `/internal` маршрутов. Не редактируйте generated-файл вручную.

## Развернуть

Для текущего Франкфурта и работающего Jarvis подготовлена [пошаговая инструкция DNS, Caddy 443, выбора тарифа и сетевых измерений](docs/frankfurt-installation.md). [Архитектура минимальной задержки](docs/latency-and-network.md) содержит аудит Jarvis, сравнение SFU/прямого WebRTC/нативного UDP и 14 открытых проектов. Прямой LAN/Bluetooth пока спроектированы, но не подключены к продукту.

Подготовить три DNS-имени и публичный IP европейского VPS, затем выполнить [инструкцию развёртывания](docs/deployment.md). Домен приложения, signaling и TURN направляются непосредственно на VPS; HTTP-проксирование Cloudflare для медиатрафика не используется.

Подробности: [архитектура и восстановление](docs/architecture.md), [дизайн и состояния](docs/frontend.md), [проверки и измерения](docs/verification.md).

Отдельный нативный захват Windows, Jarvis, запись и управление чужим компьютером — следующие возможности. Windows-приложение уже использует захват WebView2 через общий `CaptureAdapter`; отдельная реализация Windows.Graphics.Capture пока не добавлена.
