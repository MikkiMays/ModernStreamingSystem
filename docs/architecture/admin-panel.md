# Админ-панель Cord: набросок идеи (R207)

Статус: **идея без проработки** — владелец (08.11.2026): «можно сейчас не заниматься проектированием админ панели…
формирование идеи, без глубокой проработки. Сделаю это сам потом». Схема серверов — Р-110/Р-110′
(`backlog/DECISIONS.md`): A (108.165.32.75, `callcord.ru`) — разработка и админ-панель; продукт `cordcam.ru` — ядро на meet
(108.165.32.23) + узлы `fra` (meet), `hel` (B), `msk` (cordcam).

## Зачем

Один пульт, с которого владелец видит весь флот и управляет им кнопками — тем, что сегодня делается скриптами по SSH
(`deploy.sh`, `node.sh`, `maintenance.sh`, `publish-windows.sh`) и страницей «Активность» на каждом сервере отдельно.
Принцип: панель ничего не умеет сама — каждая кнопка зовёт уже существующий рычаг (админ-API ядра или скрипт), пишет
в журнал и показывает исход; если панель лежит, всё то же делается руками, как сейчас. Пользователи — владелец и
агент-сессия (через тот же API с ключом агента); GPT как исполнитель выкаток становится не нужен.

## Разделы и что они умеют

- **Обзор** — машины флота (роль, коммит, аптайм, ступень загрузки, встречи и люди), горящие алерты, последние задачи.
- **Узлы** — ступень и доли (R200 8.1), живость, комнаты; дренаж/снять дренаж; «Обновить узел» одной кнопкой (дренаж →
  ожидание конца встреч → deploy → check → снять дренаж); «Добавить сервер» формой (за ней `node-config.mjs` +
  `node.sh bootstrap/deploy`, подсказка, какие DNS-записи добавить); удалить сервер.
- **Встречи** — живые встречи с узлом и качеством, завершить встречу; статистика за период (как в «Активности»).
- **Технические работы** — окно работ R194: сейчас / запланировать / продлить / закончить; дренаж перед выкаткой.
- **Выкатки** — выкатить продукт или узел (ветка/коммит, службы, с дренажем), откатить по тегу, живой вывод, история,
  статус CI коммита, что стоит на каждой машине.
- **Безопасность и абьюз** — блокировки адресов и профилей, «щит», автоблок, отказы входа по кодам.
- **Ошибки и обращения** — ошибки клиентов по виду и версии, обращения в поддержку со статусами.
- **Метрики и журналы** — ЦП/steal/память/диск/канал машин, SFU, ядро, куратор (VictoriaMetrics на A, ссылки в
  Grafana); хвост журнала службы любой машины по кнопке.
- **Флаги возможностей** — включать и выключать функции продукта без перезапуска (сегодня — переменные `*_ENABLED`).
- **Выпуски клиента** — зеркало Windows, выпуски GitHub и CI, выкладка версии, APK, каталог серверов (подпись — у
  владельца).
- **Журнал пульта** — каждое действие: кто (владелец/агент), что, на какой машине, исход; объединён с аудитом ядра.

Данные берутся из того, что уже есть: админ-API ядра продукта (встречи, журнал, блокировки, обращения, ошибки),
`GET /api/v1/nodes` и метрики `cord_node_*`, VictoriaMetrics/vmalert/Gatus, журналы контейнеров, GitHub.

## Где живёт и как говорит с продуктом

Панель — только на A, `admin.callcord.ru`, отдельный HTML-вход веба; за ней служба `fleet` на A. Вход — Cloudflare
Access или клиентский сертификат, затем пароль пульта + одноразовый код, токен на 8 часов; на `cordcam.ru` страницы
владельца нет (`ADMIN_PASSWORD` пуст → 404). Чтение и рычаги — по уже существующей магистрали mTLS (TCP 7443) к ядру
продукта на meet с ключом пульта `X-Fleet-Key` (принимается только с 127.0.0.1, то есть из магистрали); выкатки,
откаты и добавление серверов — SSH с A ключами (`node.sh`/`node-config.mjs` выполняются на meet, где `.env` и реестр
продукта; A не хранит секретов продукта). Каждое действие пишется в аудит и на A, и в ядро продукта.

## Kubernetes или Docker

Kubernetes сейчас **не рекомендуется**. Сеть кластера (flannel VXLAN, WireGuard, Cilium) живёт на UDP, а UDP между
нашими VPS режется (замер 07.11, поэтому и магистраль — mTLS по TCP); k3s на 2-vCPU узле отнимает у SFU 0,7–1 ГБ памяти
и ≈ 10 % ЦП; rolling update противопоказан живым встречам — обновление без обрыва у нас уже сделано дренажем через
реестр; SFU всё равно один на машину с `hostNetwork`. Остаёмся на Docker Compose на каждой машине + реестр узлов +
пульт на A. Пересмотр — когда появятся ≥ 6–8 машин или выделенные серверы с частной сетью без фильтра UDP и второй
оператор.
