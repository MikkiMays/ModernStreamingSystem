# Кинозал Cord: площадки, VK Видео, Rutube, ivi, своя медиатека, «одна секунда для всех» — спецификация (одобрена владельцем 24.09.2026)

## Контекст

Владелец просит:
- изучить проект;
- переписать подсистему кинозала до уровня кода больших компаний, не меняя поведения и анимаций;
- добавить площадки VK Видео, Rutube, ivi, Кинопоиск и Зону (если получится), каждую со своей продуманной сценой, без перекрытий UI и синхронно для всех;
- кнопку «к секунде комнаты»;
- сохранённые входы в настройках с автоподключением (как токен Яндекс Музыки);
- «любой фильм или сериал с озвучками, сериями и качеством»: найти все пути, приоритет у open-source.

Проект open-source и ставится на любые сервера. Российское владелец проверит на своей установке в Москве, поэтому региональные ограничения помехой не считаются.

Постоянное разрешение: в конце каждой сессии выкатка в прод (meet.nikg.tech) и `main` актуален в обеих репах. Разрешения и правила записать в память.

Ответы владельца:
- новые площадки — отдельные карточки «Кинозала», у каждой своя сцена; сцена YouTube/Twitch с переключателем сверху слева остаётся как есть;
- «Аккаунты» — отдельный раздел настроек;
- площадки: VK, Rutube, ivi, плюс любой законный путь к «любому фильму».

Встраиваемые плееры исключены по двум причинам:
- Windows-клиент отменяет навигацию любых чужих рамок (`ModernStreamingSystem.Windows/src/Cord.Windows/Services/WebWorkspace.cs`, `FrameNavigationStarting`);
- в CSP нет `frame-src` (`infra/Caddyfile:25`).

Остаётся единственный путь: серверный прокси, как у YouTube.

## Решения

1. **Площадка — модуль.** В службе это провайдер, в вебе — запись реестра. Плеер, синхронность и прокси общие и о площадках не знают. Добавить площадку = провайдер, запись в реестре и сцена.
2. Сцена YouTube/Twitch не меняется: тот же DOM, классы, тексты, анимации. Новые карточки со своими сценами: **VK Видео, Rutube, ivi, «Моя медиатека» (Jellyfin), «По ссылке»**. Каталог личный, общим просмотр становится только по «Смотреть вместе», как сейчас.
3. **Регион не блокер.**
   - Всё страновое отдаёт сама площадка: разделы VK, бесплатное ivi.
   - Если площадка отказывает по стране, её карточка неактивна и объясняет причину (ivi — по `geocheck/whoami`).
   - Для любой установки есть необязательные настройки: `CINEMA_PROVIDERS` (какие площадки включены) и `CINEMA_PROXY` / `CINEMA_PROXY_<ID>` (выход наружу для yt-dlp, каталога и сегментов, SOCKS через `socksio`).
4. **«Аккаунты»** — новая вкладка настроек.
   - Яндекс Музыка: поле переносится из «Профиля», ключ хранения `yandexMusicToken` тот же, поведение то же.
   - Jellyfin: адрес, логин и пароль превращаются в токен; пароль не хранится.
   - Без сохранения вход спрашивается прямо в сцене (галочка «Запомнить на этом устройстве»).
   - В службе общий Fernet-сейф на комнату; сейчас он живёт внутри `yandex.py` и выносится оттуда.
5. **Одна секунда для всех.**
   - Кнопка «Встать на секунду комнаты» при расхождении больше 1,2 с становится подписанной таблеткой с числом («−3 с»).
   - Эфиры синхронизируются по `PROGRAM-DATE-TIME`: служба один раз на поток считает общую задержку `liveDelayMs`, клиент держит `hls.playingDate = serverNow − liveDelayMs` теми же порогами 0,3 / 2,5 с.
   - Без PDT остаётся нынешнее поведение: каждый у своего края.
6. **Рамки рефакторинга.** Вся подсистема кинозала: служба; ядро в части watch и правила «одна интеграция»; веб (каталог, плеер, CSS). Остальные подсистемы — следующими сессиями.
7. **Где идёт работа.** Разработка в worktree `/opt/meet/.worktrees/cinema-providers` (ветка `cinema-providers`). Слияние в `main` и выкатка — на контрольных точках A/B/C. Прод-checkout трогаю только через `pull --ff-only`.

## Архитектура

### Служба: пакет `services/cord_services/cinema/` вместо `cinema.py` (1552 строки)

```
cinema/__init__.py     Cinema (фасад) и routes под прежними именами — app.py и тесты не ломаются
cinema/wire.py         pydantic-модели ответов: Card, Page, ChannelPage, SeriesPage (новое), Details, Source, Caption
cinema/registry.py     Provider (Protocol), Features, HostPolicy, Unsupported → 400; реестр и CINEMA_PROVIDERS
cinema/catalog.py      политика кэша (Memo, TTL по типу вызова) вокруг вызовов провайдера
cinema/resolve.py      одна обёртка yt-dlp вместо _extract/_probe; hls/dash/file; субтитры; liveDelayMs
cinema/transport/      signer.py, playlists.py (rewrite, Reels), segments.py, proxy.py (fetch, manifest, image)
cinema/net.py          httpx-клиент на каждую площадку (прокси выхода); соединение только с публичными IP
cinema/providers/      youtube.py twitch.py rutube.py vk.py ivi.py jellyfin.py link.py
accounts.py            Fernet-сейф на комнату; yandex.py переходит на него без изменения поведения
```

**Интерфейс провайдера.**
- Методы: `search`, `channel`, `playlist`, `categories`, `category`, `series` (новый: сезоны и серии), `details`, `source(kind, id, options)`.
- Неподдержанное бросает `Unsupported` и отвечает 400, как сейчас.
- `features` отдаются новым маршрутом `GET …/cinema/providers` вместе с `available`, `reason` и `account`.

**Маршруты.** Пути и формы ответов прежние. Новые:
- `GET …/cinema/series`
- `GET …/cinema/providers`
- `POST …/cinema/link`
- `POST|DELETE …/cinema/accounts/{provider}`

**Укрепление без видимых изменений:**
- `fullmatch` и свой шаблон id у каждой площадки (сейчас `Resolve.contentId` не заякорен);
- подпись связывает маршрут, площадку и адрес (сейчас 24-часовая подпись картинки годится для `/fetch`);
- белый список хостов у каждой площадки, а не общий;
- без `Range` тело не буферизуется целиком сверх лимита кэша;
- ключи кэша различают регистр (id YouTube регистрозависимы);
- ожидающие `Memo` получают ту же ошибку, а не повторяют запрос по очереди;
- строки в Twitch GQL экранируются корректно;
- лимит частоты `resolve` на комнату.

При выкатке старые подписанные адреса отвалятся. Плеер сам обновит источник по 403 (`renewSource`), это одна заминка.

### Ядро (Java)
- `room/Contracts.java:79`: площадки задаются одной константой `youtube|twitch|vk|rutube|ivi|jellyfin|link`. Добавляется проверка «площадка × вид»: `channel` означает эфир и разрешён у youtube, twitch, vk, rutube и link. Шаблон `contentId` не меняется, потому что его делят игры. Все новые id в него укладываются: VK `-22277933_456242578`, Rutube и Jellyfin 32-hex, ivi число, link — непрозрачный base64url.
- `room/RoomService.java`: пять копий «одна интеграция» (addMusicService, watch.open, poker.open, durak.open, newGamesAbsent/gameStageAvailable) сводятся в один помощник. Коды и тексты ошибок прежние.
- Перегенерация `contracts/openapi.json` и `web/src/api/generated.ts` (стенд ядра, память `cord-openapi-regeneration`).

## Сцены

Общее у всех: тёмный каталог по нынешнему образцу, скилл frontend-design, без новых «эффектов».

- **VK Видео** (#0077FF).
  - Поиск «Видео и сообщества».
  - Разделы площадки лентой чипов; в РФ сами появятся «Фильмы», «Сериалы», «Трансляции».
  - Сетка 16:9: длительность, просмотры, автор.
  - Сообщество: шапка, вкладки «Видео» и «Плейлисты».
  - Ролик: «Смотреть вместе»; эфир открывается как `channel`.
- **Rutube** (цвет берётся из их CSS-бандла при реализации; до этого — общий `--blue`).
  - Полки: «Прямой эфир» (ТВ-каналы), «Сериалы и шоу» (постеры 2:3), чипы категорий.
  - Страница сериала: сезоны и серии.
  - Также страницы канала и ролика.
- **ivi** (#EA003D).
  - Вкладки «Фильмы», «Сериалы», «Мультфильмы», только бесплатное; постеры 2:3, год, жанр, рейтинг.
  - Сериал: сезоны и серии.
  - Платного нет. Если нашлось только оно: «на ivi только по подписке — показать комнате нельзя».
- **Моя медиатека** (Jellyfin, #AA5CC3).
  - Без подключения: приглашение и форма входа.
  - Библиотеки вкладками, полка «Продолжить», постеры.
  - Фильм: дорожки озвучки и субтитров. Сериал: сезоны и серии.
  - Озвучка и качество у каждого свои: меню плеера показывает `source.audioChoices`/`source.variants`, выбор делает личный `resolve`.
  - Один поток на комнату и выбор: адрес мастера мемоизируется, Jellyfin перекодирует один раз.
- **По ссылке.**
  - Поле ссылки, подсказки поддерживаемых площадок, недавние ссылки в профиле.
  - Карточка результата, затем «Смотреть вместе».

   - Код переносится в пакет дословно.

- **Перекрытия.** Каждая сцена на 320/390/500/701/767/820/1024/1280/1440: пересечение `.cinema-browser` с `.call-footer`, `.side-panel` и `.people-strip` равно 0; `scrollWidth ≤ clientWidth`. Плюс эмуляция iPhone (память `cord-web-on-phone`).
- **Синхронность.** Два браузера против прода: VOD (Rutube, VK) < 0,3 с; эфир Rutube по PDT < 0,5 с. Журнал службы подтверждает, что `resolve` и сегменты реально идут, а не только «дверь отвечает».
- **Итог:** CI обеих реп зелёный; образы в `docker compose ps` соответствуют HEAD; «О программе» показывает коммит; скилл `ModernStreamingSystem/web:verify`.

## Выкатка

1. `git -C /opt/meet/ModernStreamingSystem pull --ff-only`.
2. Откатные теги `:rollback-<дата>`.
3. `CORD_BUILD=$(git rev-parse --short HEAD) docker compose build core services gateway`.
4. `docker compose up -d --no-deps core services gateway` — SFU не трогаю, звонки не рвутся.
5. Проверки здоровья: `:8080/actuator/health`, `:18100/health`, `/api/v1/ping`.
6. `node scripts/smoke.mjs`, e2e против прода.

Windows-релиз не нужен: нативный код не меняется, а WebView2 берёт веб с сервера. Коммиты по-русски в стиле репозитория.

## Вне рамок и почему

- **Кинопоиск и платный ivi.** Видео зашифровано DRM. Ключ получает только модуль расшифровки в браузере каждого зрителя под его подпиской; сервер видит шифр и раздать его комнате не может. «Войти как на сайте» этого не меняет, а обходить DRM я не буду. Кинопоиск к тому же запрещает встраивание и закрыт по стране.
- **Зона, «балансеры» (Kodik, Alloha, Collaps, Rezka…), Lampa/TorrServer.** Это каталоги пиратского контента, и их я не интегрирую. Для «любого фильма с озвучками и сериями» есть своя медиатека (Jellyfin, open-source) и «По ссылке».
- **Вход VK.** VK Видео работает без входа. VK ID требует, чтобы владелец зарегистрировал приложение, и доступ к видео-API ему не гарантирован. Отложено до проверки.
- **Прочие подсистемы** (покер, дурак, шахматы, gartic, музыка, Telegram) — следующими сессиями.
