## Источники музыки (исследование, T18)

Пробы 20.10.2026 с этой машины, образ `modern-streaming-services` (yt-dlp 2026.8.19, deno 2.9.7):

| Источник | Как | Что вышло | Решение |
| --- | --- | --- | --- |
| **YouTube** (и YouTube Music) | yt-dlp: `ytsearch8:` для поиска, ролик по ссылке | поиск — 3 из 3 с длительностью и автором; у ролика отдельные дорожки звука: Opus 130 кбит/с (≈ 5,2 МБ на 5:20) и AAC 129 кбит/с | **добавить**: поиск и ссылка |
| **SoundCloud** | yt-dlp: `scsearch8:`, трек по ссылке | поиск работает без ключа; треки Go+ отдают только **30-секундный фрагмент** (форматы `*_preview`, `duration: 30.0`), остальные — AAC по HLS целиком | **добавить**: поиск и ссылка; фрагменты не принимаются, как превью Яндекса |
| Ссылка на файл | загрузка по адресу | работает, но адрес любой: защищать выход от внутренних адресов (`cinema/egress.py` — 750 строк ради этого) ради редкого случая — у человека обычно файл, а не ссылка | **нет**: файл загружается в два нажатия |
| Радио по потоку | ffmpeg по http | издатель играет только файлы (`-protocol_whitelist file,pipe`, `services/publisher/main.go:126`); у потока нет длительности, позиции и конца — очередь, прогресс и повтор теряют смысл; ретрансляция станции — отдельная лицензия | **нет сейчас** |
| Rutube, VK | yt-dlp | площадки видео: музыки на Rutube мало, VK Музыка — только со входом (вход не обходим); кинозал их уже открывает комнате | **нет** |

Законность. Только то, что площадка отдаёт анонимному посетителю: без входа, без DRM, без платного
слоя. Условия YouTube и SoundCloud скачивание не разрешают; Cord уже показывает YouTube всей комнате
в кинозале (решение владельца — свой плеер, без чужих рамок), и музыкальный источник не добавляет нового
рода содержимого — звук ролика, который кинозал и так включает всем. Риск назван прямо: в 2021 году
Google остановил письмами музыкальных ботов Discord (Groovy, Rythm), которые делали ровно это. Поэтому
источники выключаются одной переменной `MUSIC_SOURCES` (по умолчанию —
`upload,telegram,yandex,youtube,soundcloud`), и витрина показывает только включённые.

### Служба

- `cord_services/sources.py` — YouTube и SoundCloud через yt-dlp кинозала (`cinema.ytdlp`: тот же выход
  наружу, прокси и запасные cookies YouTube). Ссылки узнаются точным списком хостов, только отдельный
  трек; yt-dlp получает `allowed_extractors` своей площадки — общий разборщик страниц не участвует.
  Скачивание — в своём пуле из двух потоков, не дольше 150 с, не больше 50 МиБ и 60 минут; эфир и
  фрагмент — отказ словами.
- `POST /api/v1/services/rooms/{id}/music/search {source, query}` → треки (`music.search`); не больше
  20 поисков в минуту на комнату, ответ помнится 5 минут.
- `POST /api/v1/services/rooms/{id}/music/link {url, commandId}` → состояние музыки (`music.link`);
  по одному скачиванию на комнату, повтор той же команды не скачивает второй раз.
- Команда очереди `move {trackId, index}` (`music.control`): трек встаёт на место `index ≥ 1`.
- **Обложки** — `cord_services/covers.py`: JPEG 320×320, ffmpeg из встроенной картинки файла (загрузка,
  Telegram), из обложки Яндекса или миниатюры площадки. Файл — `<uuid>.jpg` рядом со звуком, живёт и
  убирается вместе с треком. В состоянии трек несёт `cover: "<uuid>"` или `null`; картинка —
  `GET /api/v1/services/music/covers/<uuid>.jpg` без заголовка входа (`<img>` его не пошлёт, CSP пускает
  только свой адрес), с `Cache-Control: private, max-age=86400, immutable`; отдаётся только обложка,
  которая есть у трека какой-нибудь очереди.
- Каталог: `sources` — включённые из `MUSIC_SOURCES`.

## Замыслы «Скоро» (для следующих эпиков; кода нет)

### Любая игра (T08)

Что это технически: **контейнер для браузерных игр**, как Activities у Discord, а не «любой exe».
Игра — веб-сборка, которую Cord раздаёт со своего адреса и запускает на сцене в `iframe` с `sandbox`
(`allow-scripts` без `allow-same-origin`, отдельный источник), без чужих сайтов в рамке (граница CONTEXT).
Связь — `postMessage`-SDK: кто во встрече, кто я, места, общий документ состояния. Ограничение, которое
решает формат: правила игр Cord живут в ядре, и чужих карт браузер не видит никогда; у сторонней игры
правил в ядре нет, значит **только игры с открытым состоянием** (викторины, «крокодил», настольные без
скрытых карт). Ядро хранит состояние игры как непрозрачный JSON с пределом размера и частоты
(`any.state`, ≤ 64 КиБ, отдельной ручкой, не в снимке — бюджет 24 КиБ). Игры со скрытой информацией —
по-прежнему модулем ядра, как покер и дурак. Начать с двух-трёх своих сборок (каталог в службе), SDK —
когда появится первый внешний автор.

### Сцена стендап (T12)

Один выступает, остальные — зал. Состояние в ядре: `stage {performerId, queue[], startedAt}`, команды
`stage.open/close/pass/hand/react`; право принести и передать сцену — класс интеграций, «поднять руку» и
реакции — любой участник. Сцена: выступающий крупно с камерой в целевом качестве (E05), зал — лентой
маленьких лиц, микрофоны зала по умолчанию выключены у себя (не у всех — модерация мягкая), реакции
(смех, аплодисменты) — всплывающими значками и общим «шумом зала» из синтеза `core/sounds.ts`, без
микрофонов зала. Делит сцену с кинозалом и столами (`RIVALS`), с музыкой — уши.

### Доска рисования (T13)

Общий холст в реальном времени. Основа — холст Gartic (`ui/GarticCanvas.tsx`: штрихи, цвета, толщины,
масштаб под экран). Штрих — вектор (точки, цвет, толщина), живьём — каналом данных LiveKit пачками по
50–100 мс, хранение — в ядре отдельной ручкой `GET /rooms/{id}/board` (дельта по ревизии) с пределом
(5000 штрихов или 2 МиБ), не в снимке. Инструменты: перо, маркер, ластик, отмена своих штрихов;
«очистить» — класс интеграций; выгрузка PNG. Делит сцену с кинозалом и столами.
