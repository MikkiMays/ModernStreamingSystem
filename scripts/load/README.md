# Нагрузка Cord: скрипты замеров (T09)

Отчёт и выводы — `docs/load/2026-11-02-load-report.md`; итоги прогонов 02.11.2026 — `docs/load/2026-11-02/*.json`.
Итоги новых прогонов пишутся в `.local/load/` (вне git; `LOAD_OUT` меняет каталог).

Перед любым прогоном — **нет ли живых встреч** (`backlog/bin/active-meetings.sh`): тестер и SFU делят один процессор.
Ничего из этого не трогает данные стенда: SFU-тестер работает в своих комнатах `lt-*`, ядро — теневое, со своей базой.

| Что | Как | Что меряет |
| --- | --- | --- |
| SFU | `python3 sfu_run.py NAME [--rooms N] [--max-participants M] -- <аргументы lk load-test>` | ядра и память SFU по cgroup, ЦП/steal хоста; отдачу и потери — в логе тестера (`│ Total`) |
| Серии SFU | `./batch1.sh` (simulcast, вебинар, комнаты, звук), `./batch2.sh` (как в Cord: один слой, все смотрят всех; музыка) | ≈ 30 мин |
| Музыка | `python3 music_run.py NAME БОТОВ СЛУШАТЕЛЕЙ [сек]` | ЦП и память издателей (Go + ffmpeg) и SFU; файл — розовый шум (создаётся сам) |
| Теневое ядро | `./core-shadow.sh up` / `down` | образ `modern-streaming-core` на :18080 со своими Postgres :15432 и Redis :16379, пределы антибота сняты; SFU общий |
| Ядро: события | `python3 cgrun.py NAME --warmup 15 lt-core,lt-pg,lt-redis -- node corelt.mjs КОМНАТ ЛЮДЕЙ ЧАТ_МС СЕК` | задержка «отправил → событие у соседей», перечитывания снимка, трафик снимков, ЦП ядра и базы |
| Ядро: доска | `... -- node boardlt.mjs КОМНАТ ЛЮДЕЙ КУРСОР_МС ПРАВКА_МС СЕК` | задержка курсора и правок у соседей |
| Ядро: входы | `... -- node joinlt.mjs ФОН ВСЕГО ПАРАЛЛЕЛЬНО` | входов в секунду и их задержка при N строк `rooms` |
| Все прогоны ядра | `./batch-core.sh` | перед каждым — чистое теневое ядро |
| Схема для доски | `python3 board/render_board.py board/diagram.json out.cord-board board/layout.json`; предпросмотр — `node board/preview.mjs out.cord-board out.png 0.4` | файл открывается на доске Cord: «Ещё» → «Открыть файл» → «Заменить доску» |

Ограничения метода: тестер `lk load-test` стоит на той же машине (трафик идёт через `lo`, не через сетевую карту) и
съедает столько же ЦП, сколько SFU, — поэтому переносимы **ядра SFU на мегабит/пакет**, а не «сколько выдержала
машина»; канал меряется отдельно (`iperf3` до внешнего сервера). Тестер не согласует RED — у Chrome звук и музыка
идут с RED и весят в 2–3 раза больше. Нагрузчики ядра (Node) тоже делят ЦП с ядром — задержки под нагрузкой
завышены, ЦП ядра и базы — нет (cgroup).
